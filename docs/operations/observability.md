# Observability and service objectives

Verus telemetry exists to operate the service without copying the content it protects. Logs,
metrics, and traces may contain bounded component names, normalized routes, operation names,
outcomes, stable reason or error codes, durations, attempt numbers, correlation IDs, trace IDs, and
span IDs. They must not contain tenant or user identifiers, job or scan IDs, object references,
URLs, source content, extracted text, prompts, model output, portfolio values, credentials, request
bodies, exception messages, or stack traces.

## Correlation and traces

The API accepts `x-correlation-id` only when it matches the bounded public syntax; otherwise it
creates a new ID. It accepts W3C version-00 `traceparent` only when the trace and parent span IDs
are nonzero. Responses return the effective correlation ID and trace context.

Use `AsyncLocalStorage` only inside one process. Propagate `x-correlation-id` and `traceparent` on
trusted service calls. Durable jobs store the correlation ID as envelope metadata and return it to
the claiming worker. Workers create a child span before retrieval, parsing, model, policy, evidence,
signing, or delivery work. Audit events generated by that operation use the same correlation ID.
Correlation is for investigation, not authorization, tenancy, idempotency, or cache keys.

## Logs, errors, and metrics

Use `StructuredLogger`; do not call `console`, serialize an `Error`, or attach arbitrary objects in
runtime code. The logger emits a closed JSON schema and converts failures to stable public error
codes. Collector failure cannot change request or job behavior.

Use only the metric definitions exported by `SafeMetricRegistry`. Labels are exact, syntactically
bounded, and capped at 200 series per metric by default. Normalize HTTP routes before recording
them. Correlation, trace, tenant, user, job, scan, artifact, and object identifiers are forbidden as
metric labels. The OpenMetrics endpoint must be operator-authenticated or isolated on a private
listener when exposed by a deployment.

## Initial service objectives

These are initial operating objectives, reviewed after representative load testing and frozen for
the v1.0 release gate:

| Service level indicator                     | Rolling objective  | Measurement                                                     |
| ------------------------------------------- | ------------------ | --------------------------------------------------------------- |
| API availability                            | 99.9% over 30 days | Non-5xx responses for admitted requests, excluding planned work |
| Accepted scan durability                    | 99.99%             | Accepted scans with a durable job or terminal audit record      |
| Ready-job start latency                     | 99% under 60 s     | Time from `available_at` to first valid lease                   |
| Correlation completeness                    | 99.99%             | Sampled flows joined across API, queue, worker, and audit       |
| Context Capsule result-commit conflict rate | below 0.01%        | Effect-key conflicts divided by completion attempts             |

Availability has a 43.2-minute monthly error budget. Page when the one-hour burn rate exceeds 14x or
the six-hour burn rate exceeds 6x; ticket when the three-day burn rate exceeds 1x. Also page on
sustained oldest-ready age above five minutes, inability to commit audit records, or rapid
dead-letter growth. Alert on missing telemetry separately; absence of signals is not health.

## Incident and retention rules

Start with correlation and trace IDs, then pivot to tenant-scoped audit tooling under authorization.
Never paste payloads or credentials into log search, incident chat, or metric annotations. If a
restricted value reaches telemetry, treat it as a security incident: stop the producer, restrict
collector access, rotate affected credentials, purge where supported, preserve an access audit, and
document residual copies in backups.

Operational telemetry retention is environment policy, not an application default. Hosted production
must document hot-search and archive periods, access roles, encryption, regional location, deletion
behavior, and backup expiry before traffic. Rollback may disable a new signal but must not broaden
fields, lower access control, or drop correlation from in-flight durable jobs.
